# 状态栏快捷面板

参考 [Magpie 的紧凑面板](https://usemagpie.ai/img/panel-light.png)，将常用状态与操作放在 420 × 570 逻辑像素的窗口中。沿用主界面的 Radix Themes、绿色强调色、13px 正文与无阴影模块；主窗口仍保留全部管理功能。

## 信息与操作

- 网关：显示实际运行、停止或异常状态，复制当前监听地址；启用供应商数量明确标注为“已启用”，不表示上游健康检查结果。
- 客户端：单独开关 Codex、Claude Code、Pi 接管。Codex 默认模型使用已有可路由模型列表与校验；Claude / Pi 沿用自身的模型选择机制。
- 今日用量：从本地成功路由记录读取调用、总 Token 与输出 Token，按本地日期统计。读取失败保留其他可用功能并提示刷新。
- 路由、使用统计、设置入口打开对应主窗口页面；主窗口的未保存路由保护继续生效。另保留打开主窗口与退出操作。
- 面板打开时每 8 秒刷新；收起后停止轮询，重新打开立即刷新。失焦、Escape、再次点击托盘或关闭按钮收起面板；Escape 优先关闭打开的 Radix 选择菜单。
- 设置页可隐藏状态栏图标，偏好单独原子写入 `tray-preferences.json`，不改动既有管理配置格式。隐藏图标后仍可重新启动应用进入主窗口；macOS Dock 的重新打开事件也显示主窗口。

## 平台差异

| 平台    | 图标                                         | 打开面板                                              | 窗口处理                                                                        |
| ------- | -------------------------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------- |
| macOS   | 18pt 单色模板，36px RGBA 提供 2× 图像        | 左键 / 右键均直接在所点状态栏图标下方展开，无系统菜单 | 可接收键盘的非激活式 NSPanel，不成为主窗口；加入全屏空间，避开菜单栏与 Dock     |
| Windows | 64px 绿色图标，由系统按 DPI 缩放             | 左键 / 右键均直接打开面板，无系统菜单                 | 按任务栏所在边缘和目标显示器缩放定位，不进入任务栏                              |
| Linux   | 彩色图标，依赖桌面的 AppIndicator / 托盘支持 | 原生菜单的“打开快捷面板”                              | Tauri 不提供 Linux 托盘点击事件；X11 尝试工作区定位，Wayland 允许合成器选择位置 |

macOS / Windows 不绑定原生菜单，并明确关闭托盘右键菜单的默认行为。左右键共用同一个处理入口，仅在松开时触发一次；同屏再次点击收起，关闭按钮和 Escape 仍可收起。Linux 因 Tauri 不提供托盘点击事件，保留原生菜单中的“打开快捷面板”入口。

macOS 直接从 `NSStatusBarButton` 获取屏幕矩形，使用 `NSScreen.frame` / `visibleFrame` 的 AppKit 逻辑坐标计算图标下方的位置；不混用 Tauri 的物理位置、主屏缩放或上次窗口所在显示器。镜像菜单栏暴露的按钮属于另一屏时，按本次点击所在屏幕的菜单栏重新计算锚点。支持左 / 右 / 上 / 下布局、负坐标、不同 Retina 缩放及小工作区；尺寸不足时缩小面板，内容滚动。面板打开后，同屏再次点击收起，另一屏点击则移到该屏。

`tray_surface` 保留隐藏的 Tauri 窗口负责 IPC 生命周期，仅把原有内容视图和键盘响应视图挂到新建的 `NSPanel`。非激活属性在面板创建时设置，不修改已有系统窗口的类，不使用私有 API。面板不进入主窗口循环，也不激活整个应用或调用主窗口的显示方法；原生焦点回调负责收起与轮询生命周期。只有明确选择主窗口、路由等入口才打开完整客户端。弹出失败只报告错误，不自动唤起主窗口。

Windows / Linux 延用各平台的无标题栏托盘浮层，按物理工作区、目标显示器比例和图标位置定位，覆盖四侧任务栏。Wayland 拒绝绝对定位时交给合成器处理，并保留关闭按钮与菜单入口。

图标遵循 Apple 的[菜单栏设计](https://developer.apple.com/design/human-interface-guidelines/the-menu-bar)与[模板图像](https://developer.apple.com/documentation/appkit/nsimage/istemplate)规则：macOS 素材只有黑色与透明通道，不绘制彩色底块，不自行决定明暗 tint。Tauri 以 template 模式交给 AppKit。箭头表达切换语义，使用 XXSwitch 自有图形；Windows / Linux 保留绿色底块以兼容不同托盘背景。

`scripts/generate-tray-icons.swift` 可在 macOS 重新生成 SVG、1× / 2× PNG 与内嵌 RGBA。生成产物随源码提交，Windows / Linux 编译不依赖 Swift。平台能力依据 [Tauri 系统托盘文档](https://v2.tauri.app/learn/system-tray/)。

## 数据与窗口边界

`tray.rs` 提供六个专用命令：汇总快照、单项客户端修改、面板操作、读取显示偏好、设置显示偏好、消费主窗口导航。快照不返回供应商凭据、原始配置或 Skills 路径。面板只授予事件监听能力；快照、变更、面板操作检查调用窗口，导航消费仅允许主窗口。

单项变更先读取最新状态，保留原有版本检测，再复用主窗口的模型校验、配置保存、接管应用和路由启动逻辑。成功后通知主窗口刷新，未修改的草稿随状态更新，已有编辑保留。持久化后应用配置发生错误时，面板重新读取当前状态并保留错误信息，避免显示过时开关。

## 隔离验证

运行 `pnpm dev:ui` 后访问 `http://127.0.0.1:1422/?view=tray`，仅浏览器模拟 IPC。预览工具栏显示两种平台图标和外观切换；模型、开关、导航、隐藏图标与退出均不调用原生系统。正式构建排除该工具栏和模拟模块，使用真实后端。

本地验证包括：

- `pnpm test:ui`：现有 UI 命令回归、托盘单项变更、模型限制、显示偏好、导航消费、模拟退出隔离、草稿保留及生产资源隔离。
- `cargo test --locked --manifest-path src-tauri/Cargo.toml tray`：8 项测试，覆盖左 / 右键松开时直接触发（按下不触发、中键不触发）、四边任务栏、缩放、负坐标、镜像菜单栏的第二屏锚点、上下左右多屏布局及小工作区，另验证模板图标、单项修改和模型校验。
- macOS `cargo run --locked --manifest-path src-tauri/Cargo.toml --example tray_surface_probe`：使用真实承载代码创建隐藏面板，检查原生类为 `NSPanel`、非激活属性、键盘能力、不会成为主窗口、实际 WKWebView 的归属与 320 × 240 / 420 × 570 下的尺寸同步；使用正式版相同的图标构造器，确认原生状态栏图标没有绑定系统菜单。修复前同一检查失败于普通 `NSWindow`，修复后通过。探针不加载管理状态、接管配置、路由器或真实业务插件。
- 浏览器预览：浅色 / 深色、正常 / 空 / 未运行状态、模型切换、客户端开关、收起与重开、菜单与面板 Escape、设置显示偏好、跨窗口外观同步；默认尺寸下内容完整展示。
- macOS 原生编译、Apple Silicon / Intel 通用生产包、签名与 DMG 只读挂载校验。Windows 编译由分支 `windows:check` 执行，Linux 编译包含在现有 MR Clippy 检查中；Clippy 严格模式受原有代码告警影响。

先运行 `pnpm build`，再用 `cargo run --locked --manifest-path src-tauri/Cargo.toml --example tray_surface_probe --features tauri/custom-protocol -- --preview` 可运行独立的原生模拟面板，加载编译后的面板资源与 `examples/support/tray_preview_fixture.rs` 的合成 IPC；无主窗口、路由器或配置写入，退出只结束该预览进程。该示例不会进入生产客户端；正式包只有真实后端。

开发期间未安装或重启用户正在使用的 XXSwitch。原生类型和视图尺寸探针、多屏坐标回归已通过；图形控制工具未能连接独立预览程序，因此这次没有将菜单栏点击、全屏 Spaces 和多屏切换报告为实机交互验证通过。Windows / Linux 桌面交互也仍需实机检查。
